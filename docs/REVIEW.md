# 0.1.0 검토 및 검증

초기 릴리즈로 Git 비교 기준이 없어 전체 소스·테스트·빌드 스크립트를 검토했습니다. review-agent 지침에 따라 읽기 전용 검토를 먼저 수행하고 이후 구현 단계에서 수정했습니다.

## 발견 후 수정

| 우선순위 | 문제 | 수정 |
| --- | --- | --- |
| P2 | macOS 27 메뉴는 이미지 지정만으로 미리보기를 표시하지 않을 수 있음 | 아이콘 항목의 preferredImageVisibility를 visible로 지정 |
| P2 | 시계/앱 실행 변화로 숨김 재적용 시 응답 지연에 제한이 없었음 | 모든 재적용에 8초 복구 타이머 적용 |
| P2 | 전역 키 이벤트 모니터가 앱 내부 Control+F8을 받지 못함 | 로컬 모니터도 복구 처리 |
| P2 | 손쉬운 사용 권한 철회 후 기존 숨김 제한이 남을 수 있음 | 권한 철회 감지 시 모두 펼침 |

최소 실행 버전도 실제 구현에 맞춰 27.0으로 정리했습니다. 이 검토에서 추가로 확정한 미수정 결함은 없습니다.

## 확인 범위

- macOS 27.0.1 · Apple Silicon에서 컴파일, plist 및 코드 서명 무결성 검사.
- 숨김 대상 계산: 경계, 읽지 못한 좌표, 양쪽에 걸친 앱, 빈 목록.
- 자기 앱/시스템 앱 보호 및 5가지 아이콘의 1·2·3배 실제 픽셀 렌더링.
- 두 점이 두 상태에서 가로 형태를 유지하고 기존 fold 설정이 캡슐로 이어지는지 검사.
- 손쉬운 사용 권한 없는 프로세스에서 숨김 요청이 설정을 유지하고 모두 표시하는지 검사.
- 사용자의 이전 설치 빌드 접기·펼치기 정상 동작 확인 보고.

현재 변경된 메뉴 미리보기의 실제 우클릭 팝업 화면은 자동화가 메뉴 막대 요소를 화면 밖으로 판정해 시각 검증을 완료하지 못했습니다. API 지정과 렌더링은 확인했으며 최종 배포 빌드의 실기 확인 항목으로 남깁니다.

여러 모니터, 장시간 실행, 재부팅, 강제 종료 복구 및 다른 macOS 27 버전은 미검증입니다. 비공개 API 의존성과 미공증 상태를 README와 릴리즈에 명시했습니다.


## 0.2.0 개발 검증: 이동 후 숨김 갱신 수정

접힌 상태에서 오른쪽 아이콘을 왼쪽으로 옮겨도 기존 hiddenIDs 목록을 재사용하던 문제가 있었습니다. 전역 포인터 이벤트에서 메뉴 막대의 Command 드래그 시작과 마우스 해제를 추적하고, 펼쳐진 배치를 다시 읽어 적용하도록 수정했습니다. Command 키를 먼저 놓는 경우에도 추적한 이동을 완료합니다.

회귀 검사는 실제 AppDelegate의 접기·이벤트 처리 경로를 실행하며 좌표 공급과 비공개 표시 서비스만 대체합니다. 수정 전 `zsh scripts/reorder-check.sh`는 “moving an item to the hidden side must refresh the hidden set”에서 실패했고 수정 후 통과했습니다. 오른쪽으로 다시 이동, 다른 창에서의 드래그 무시, 지연 중 명시적 펼치기 취소도 검사합니다. 이는 실제 macOS 좌표·드래그 이벤트 전달을 대신 보장하는 검사는 아닙니다.

UI는 두 선택 메뉴의 상태 열을 숨기고, 선택 항목에 강조 색·굵은 글꼴·‘사용 중’ 표시를 적용했습니다. 실제 우클릭 메뉴 화면은 자동화의 화면 밖 요소 오류로 별도 사용자 확인이 필요합니다.

수정 빌드를 /Applications에 설치한 뒤 재등록된 권한의 앱 판정이 true임을 확인했습니다. 실제 접기·펼치기 UI 전환과 접힌 상태의 활성 assertion, 적용 완료·오류 없음, 자기 앱 제외를 읽기 전용 디버거 검사로 확인했습니다. 실제 Command 드래그 왕복과 우클릭 시각 확인은 사용자 확인을 요청한 상태입니다.


## 0.2.0 개발 검증: 메뉴 선택 표시 수정

이동 갱신 개발 빌드에서 상태 열을 숨겨도 체크 상태를 유지한 항목에 macOS가 체크를 표시하는 문제가 사용자 확인으로 드러났습니다. 모든 선택 항목의 NSMenuItem.state를 off로 고정하고, MenuChoiceRow가 전체 행을 그리도록 바꿨습니다. 부가 문구·기본 이미지·attributedTitle을 제거했으며 선택 상태는 배경과 전경 대비 및 접근성 값으로 표현합니다.

같은 생산 코드의 행 뷰를 사용한 별도 미리보기 앱에서 실제 NSMenu 팝업을 띄워 두 선택 메뉴의 체크·체크 여백·부가 문구가 없는 화면을 확인했습니다. 캡슐 클릭 후 메뉴를 다시 열었을 때 캡슐만 반전되는 동작을 확인했습니다. 기존 숨김 계산·권한 거절·드래그 갱신 회귀 검사도 통과했습니다.


## 0.2.0 개발 검증: 시스템 아이콘 숨김

MenuBarAgent의 접근성 식별자를 확인된 시스템 번호로 변환해 일반 앱과 별도로 숨김 대상을 계산합니다. 시스템 아이콘만 있는 경우의 실제 AppDelegate 적용 경로, Wi‑Fi와 배터리의 독립 선택, 읽지 못한 좌표, 양쪽에 걸친 동일 항목, 미확인 식별자 유지 및 숨겨진 시계·제어 센터의 hover 제외를 검사합니다. 커피콩 자체는 항상 표시합니다.

구형 메뉴 플러그인 제거·복구나 지속 복구 도우미는 적용하지 않았습니다. 구형 항목은 프로세스 단위로 처리될 수 있습니다. 최종 빌드 권한 재등록 후 실제 MenuBarAgent 접근성 트리에서 Wi‑Fi 숨김·복원을 확인했습니다. 펼치기에는 Wi‑Fi가 있고 접기에는 없으며 배터리·시계·제어 센터와 Barista는 유지됐습니다. 설정 창을 닫은 뒤 3초 자동 접기에서도 Wi‑Fi가 사라지고 Barista가 남는 것을 확인했습니다. 설정 창이 열린 동안 자동 접기를 미루는 동작과 구분해 검사했습니다. 접근성 트리 확인이며 자동화의 메뉴 막대 스크린샷은 빈 화면으로 반환되어 실제 픽셀 화면 검증은 사용자 확인이 필요합니다.


## 0.2.0 개발 검증: 접기 속도 및 사용 중 대기

AX 위치 조회를 최대 8개 작업으로 병렬 처리하고 결과 순서를 유지합니다. 16개 프로세스가 각각 20ms 기다리는 검사에서 순차 최소 320ms에 비해 약 49ms를 측정했습니다. 실제 macOS 서비스 적용 지연까지 보장하는 수치는 아닙니다.

다른 앱의 메뉴 열림·닫힘 알림, 메뉴 막대 포인터 및 클릭 후 새로 표시된 떠 있는 창을 감지합니다. 창 내용이나 제목은 읽거나 저장하지 않습니다. 일반 레벨의 앱 창은 팝업 감지 대상에서 제외합니다. 실제 AppDelegate 타이머 검사에서 사용 중 3초 이상 유지, 사용 종료 후 전체 3초 재시작, 사용 중 수동 접기 및 기존 드래그 갱신을 확인했습니다. 메뉴 감지 자체와 최종 빌드의 실제 팝업 사용은 권한 재등록 후 추가 검증이 필요합니다.


## 0.2.0 개발 검증: P2 검토 지적 수정

마우스 이벤트 및 자동 접기 판단은 캐시만 읽습니다. 접근성·창 목록의 주기 검사는 백그라운드에서 중복 없이 실행하고, 클릭 위치에서 아이콘 소유자를 별도로 확인합니다. 팝업 추적은 해당 프로세스로 제한하며, 확인된 시스템 아이콘에 한해서 관련 시스템 호스트를 포함합니다. 아이콘 소유자를 확인할 수 없으면 무관한 프로세스로 범위를 확장하지 않습니다.

회귀 검사에서 1,000회 포인터 확인이 외부 조회를 발생시키지 않고, 100회 주기 검사 요청이 진행 중인 조회 하나로 제한되는 것을 확인했습니다. 다른 앱의 떠 있는 창 제외, 클릭한 앱의 팝업 감지 및 팝업이 닫힌 뒤 다른 앱의 창이 남아도 대기가 해제되는 동작을 검사했습니다. 기존 타이머·수동 접기·시스템 아이콘·드래그 회귀 검사도 통과했습니다. 최종 앱의 실제 아이콘 소유자 판정과 팝업 감지는 권한 재등록 후 확인해야 합니다.


## 0.2.0 개발 검증: 자동 접기 영구 대기 진단

실행 중 앱에서 Chrome(pid 1519)의 열림 토큰 1701801278이 남아 있었지만 팝업 추적·메뉴 포커스·조회 중 상태는 모두 비어 있었습니다. 같은 기록을 실제 MenuInteractionMonitor에 재생한 `zsh scripts/interaction-check.sh`가 수정 전 “a lost menu-close notification must not block automatic collapse forever”로 실패했습니다. 닫힘 알림 수신만이 기록을 해제하던 구조가 원인입니다. 닫힘 이벤트가 누락됐는지 서로 다른 토큰으로 도착했는지는 기록만으로 구분할 수 없습니다.

열림 알림 직후 짧은 생성 유예를 두고, 실제 메뉴 창·메뉴 포커스·팝업 추적과 주기적으로 대조해 오래된 이벤트를 정리합니다. 보이는 메뉴에는 무조건 시간 제한을 걸지 않습니다. 기존 bool 대체 검사 대신 실제 메뉴 기록·주기 샘플러·AppDelegate 타이머를 연결한 회귀 검사를 추가했습니다. 정식 빌드의 동일 증상 복구는 최종 권한 재등록 후 확인해야 합니다.

권한 재등록 후 /Applications/Barista.app 0.4.3의 설정에서 권한 완료, 자동 접기 활성화, 5초 선택을 확인했습니다. 완료 버튼으로 설정 창을 닫은 직후 MenuBarAgent 접근성 트리에는 Wi‑Fi와 “아이콘 접기”가 있었고, 6.5초 대기 후 Wi‑Fi가 사라지며 Barista가 “숨긴 아이콘 펼치기”로 전환됐습니다. 실제 유휴 상태 자동 접기와 커피콩 유지가 확인됐습니다. 실제 외부 메뉴·팝업을 사용하는 동안의 대기는 메뉴 막대 클릭 도구 제한으로 이번 실기 검증에 포함하지 못했으며 회귀 검사 범위로 남습니다. 재등록 후 앱 바이너리를 다시 빌드하거나 변경하지 않았습니다.

## 0.2.0 공개 전 최종 검토

review-agent 기준으로 첫 공개 버전 0.1.0 이후 전체 변경 및 새 파일의 호출 경로와 회귀 검사를 검토했습니다. No findings. 새로 확인된 조치 가능한 결함은 없습니다. `zsh scripts/check.sh` 전체 검사와 `git diff --check`가 통과했습니다. 배포 ZIP의 SHA256SUMS 검증이 통과했고, build와 /Applications의 실행 파일 SHA-256이 일치합니다. 이 검토 당시에는 실기 검증한 앱을 재빌드 없이 배포했습니다. 여러 모니터·장시간 실행·재부팅·다른 macOS 27 버전 및 실제 외부 팝업 사용 검증의 제한은 유지하며 Preview로 공개합니다.

## 공개 버전 정리

첫 공개 버전은 0.1.0, 후속 기능·수정 묶음은 0.2.0으로 통합했습니다. 위 실기 검증의 0.4.3 표기는 당시 개발 빌드의 이름이며 기능 검증 이력으로 남겼습니다. 공개 CHANGELOG는 두 릴리즈만 기록합니다. 이후 로컬 수정·테스트는 공개 버전을 유지하며 내부 빌드 번호만 증가시킵니다. 0.2.0의 내부 빌드 번호는 10입니다.
