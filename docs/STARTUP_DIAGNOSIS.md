# 재부팅 후 일부 아이콘만 숨겨지는 동작의 사전 검사

2026-10-02. 설치 앱과 생산 코드는 변경하지 않고 AppDelegate의 실제 실행 알림 경로를 검사했다. 이번 요청은 재부팅 시 재발 가능성 확인이므로 수정·설치 단계는 수행하지 않았다.

## 확인된 동작

숨김 대상(hiddenIDs, hiddenSystemIDs)은 메모리에만 있으며 재시작 때 빈 목록에서 출발한다. 새로 접을 때 현재 아이콘 좌표를 읽어 다시 계산하는 구조이므로, 이 자체는 저장 데이터 유실을 의미하지 않는다.

하지만 첫 접기 이후 다른 로그인 앱의 아이콘이 왼쪽에 나타나면, 앱 실행 알림에서 applyRestriction()만 호출한다. 이 함수는 현재 실행 앱 목록은 갱신하나 숨김 대상은 기존 목록을 재사용한다. 따라서 새 아이콘이 숨김 대상에 포함되지 않을 수 있다.

## 재현 및 대조

Tests/StartupChecks.swift는 AppDelegate를 직접 시작하고 첫 아이콘을 접은 뒤 두 번째 왼쪽 아이콘을 추가한다. NSWorkspace.shared.notificationCenter에 실제 앱 실행 알림 이름을 게시한다. 좌표 공급과 비공개 숨김 서비스는 대체하며 실제 재부팅이나 운영체제의 로그인 실행 순서는 재현하지 않는다.

```sh
zsh scripts/startup-check.sh
# Launch replay: hidden=1, scans=1, restrictions=2
# RED: a late login icon on the hidden side remains visible after the app-launch notification
```

같은 실행 파일을 반복 실행해 동일하게 실패했다. 두 아이콘과 실행 알림만 포함한 작은 시나리오다. 기존 검사는 드래그 경로만 다뤄 이 경우를 잡지 못했다. 검사 실패는 현재 결함을 고정한 예상 결과이며 scripts/check.sh에는 포함하지 않았다.

```sh
zsh scripts/startup-check.sh --rescan
# Launch replay: hidden=2, scans=2, restrictions=3
# PASS: late login icons are included in the hidden selection

.build/startup-checks --restart
# Restart replay: hidden=2, scans=2
# PASS: restarting with ready icons reconstructs the full hidden selection
```

새 위치 계산만 수행하면 통과하고, 아이콘이 준비된 상태에서 Barista를 새로 시작해 접어도 통과한다. 이것은 저장 목록 복구 실패보다 실행 중 숨김 대상 갱신 누락과 맞는다. 이번 사용자의 재부팅 증상이 반드시 이 원인이었다고 확정할 수는 없다. 첫 접기와 다른 앱의 아이콘 생성 순서에 따라 재발할 수 있으며 매 재부팅마다 발생한다고 단정할 근거는 없다.

## 수정 시 확인할 사항

앱 실행·메뉴 아이콘 생성 후 위치를 다시 읽어 숨김 대상을 갱신하는 경로가 필요하다. 알림과 실제 아이콘 생성의 시간차, 이미 접힌 배치의 좌표 변형, 제한 해제 후 레이아웃 반영 지연을 함께 고려해야 한다. 기존 목록에 새 bundleID를 무조건 추가하면 오른쪽에 두려는 앱까지 숨길 수 있으므로 위치 확인을 생략해서는 안 된다.

실제 재부팅, 손쉬운 사용 서비스의 초기 준비 지연, macOS의 아이콘 순서 복원 및 Command 드래그 이벤트 전달은 이번 검사에서 검증하지 않았다.

## 수정 및 회귀 검사 (내부 빌드 11)

앞의 실패 기록은 수정 전 결과다. 현재 AppDelegate는 이미 숨긴 목록을 유지하며, 새로 실행됐거나 첫 접기에서 아직 위치를 읽지 못한 앱을 약 30초 동안 재확인한다(메뉴 사용 중 대기 시간 제외). 현재 표시된 배치에서 Barista와의 상대 위치를 두 번 확인한 앱만 새로 숨긴다. 오른쪽·읽지 못한 아이콘은 계속 표시한다. 앱을 재실행하면 그 앱의 이전 숨김 제한만 잠시 해제해 새 위치를 확인한다. 확인된 시스템 아이콘도 같은 기간에 재확인한다.

수동 펼치기·드래그·종료는 이전 조회를 취소한다. 메뉴 사용·임시 펼치기·기존 적용 작업 중에는 기다리며, 조회 도중 Barista 위치가 바뀌면 그 샘플을 적용하지 않는다. 비공개 API 적용 실패는 기존 전체 표시 복구 경로를 사용한다.

권한이 이미 허용된 시작에서도 자동 접기 타이머를 시작한다. 자동 접기의 첫 조회가 비어 있으면 로그인 준비 기간에는 조용히 재시도한다. 이때 설정 창을 자동으로 열어 후속 접기를 막지 않는다. 수동 접기의 안내는 유지한다.

`zsh scripts/startup-check.sh`는 이제 정상 통과해야 하며 전체 `scripts/check.sh`에 포함했다. 검사에는 늦은 실행 알림, 실행 후 더 늦은 아이콘 생성, 읽지 못한 좌표의 복구, 오른쪽 아이콘 유지, 기존 숨김 유지, 늦은 시스템 아이콘, 수동 펼치기 시 취소, 기존 권한에서 자동 접기 시작, 첫 조회가 완전히 빈 시작의 복구가 포함된다. 이전 조사용 `--rescan`·`--restart` 옵션은 대조 검사 기록으로만 남으며 현재 검사에는 필요하지 않다. 재실행한 앱의 오른쪽 복원과 메뉴 사용 중 조회 대기도 검사한다.

30초보다 늦게 나타나고 추가 실행 알림도 없는 아이콘은 자동 발견을 보장하지 않는다. 실제 재부팅과 macOS의 순서 복원은 별도 실기 검증 범위다.

## 설치 및 실기 확인

내부 빌드 11을 /Applications/Barista.app에 설치했다. 코드 서명 무결성 검사가 통과했고 build와 설치 실행 파일의 SHA-256이 일치했다. 사용자가 현재 빌드의 손쉬운 사용 권한을 다시 연결한 뒤 권한 완료를 확인했다.

별도 로컬 검사 앱을 Barista가 접힌 뒤 실행했다. 검사 앱은 처음에는 메뉴 아이콘 없이 실행하고, 나중에 버튼으로 실제 NSStatusItem을 생성했다. 생성된 아이콘은 자동 숨김 상태에서 MenuBarAgent 접근성 트리에 나타나지 않았고, Barista를 펼치면 ‘Barista 지연 로그인 검사 아이콘’이 나타났다. 다시 접고 포인터를 메뉴 막대 밖으로 옮겼을 때 검사 아이콘은 사라졌으며 Barista의 ‘숨긴 아이콘 펼치기’ 버튼은 남았다. 이 확인은 실제 AppKit·접근성 위치 조회·비공개 표시 서비스를 사용한 결과다. 검사 앱은 종료하고 파일을 제거했다.

최종 전체 회귀 검사와 초기 시작 검사의 반복 실행이 통과했다. 회귀 검사는 실제 사용자의 다른 앱 실행 알림·키 입력이 결과를 바꾸지 않도록 NotificationCenter와 입력 판정을 분리했다. 생산 실행에서는 실제 NSWorkspace 알림과 NSEvent 판정을 사용한다. 디버그 로그는 생산 코드에 추가하지 않았다.

컴퓨터 재부팅 자체는 실행하지 않았으므로 다음 실제 로그인에서의 macOS 순서 복원·서비스 준비 시간은 미검증 범위로 남는다.

## 사용자 재부팅 확인 (2026-10-03)

사용자가 내부 빌드 11을 사용해 실제 재부팅 후 정상 동작을 확인했다. 이 결과와 수정 사항을 0.2.1 Preview로 배포한다. 다른 로그인 앱 조합·여러 모니터·다른 macOS 버전까지 검증한 것은 아니다.
